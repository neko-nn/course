# 💖 NPC好感度系统使用指南

## 📚 概述

赛博小镇的NPC拥有**好感度系统**,每轮对话结束后由LLM分析玩家态度,把变化量累加到该NPC的档案里,并影响后续对话的语气与配合度。

需要先说明一条代码现状:**梓涵(导游)不打分**。`agents.chat` 里对 `npc_name == "梓涵"` 直接跳过情感分析，所以 `/affinities` 也只返回四位专家。

---

## ✨ 核心功能

### 1. **自动情感分析**
- 🤖 用 `RelationshipManager` 调一次LLM（`chat_with_tools`，不带工具）
- 📊 判断玩家态度 (友好/中立/不友好)
- 🎯 评估互动质量 (深入/一般/敷衍)
- 💬 识别情感倾向 (赞美/批评/中性)
- 🧩 解析失败时按"不变化"处理，不影响对话主流程

### 2. **好感度动态调整**
- 📈 友好对话提升好感度 (+1 到 +10)
- 📉 批评对话降低好感度 (-3 到 -15)
- 💾 变化量通过 `memory.update_fact("affinity", ...)` 直接写入 `memory_data/<NPC>/profile.json`
- 🎚️ 接口返回时裁剪到 0-100（**注意**: 写进档案的原始值不做裁剪，见下文常见问题）

### 3. **关系等级系统**
- 🥶 **陌生** (<20): 冷淡疏离,不太愿意多说
- 😐 **熟悉** (20-40): 礼貌但略显生疏
- 😊 **友好** (40-60): 礼貌友善,正常交流
- 🤗 **亲密** (60-80): 友好热情,愿意多聊
- 💕 **挚友** (≥80): 非常热情,像老朋友一样

### 4. **对话风格调整**
- 🎭 每轮构造系统提示词时，`get_context_prompt()` 会把"当前好感度: X/100"写进人设
- 💬 高好感度: 更热情、更愿意分享
- 😶 低好感度: 更冷淡、回答简短
- 🔄 动态调整,实时生效（下一轮对话就能感受到）

## 🔧 技术实现

### 架构设计

```
RelationshipManager
├── llm: LLM                          # 情感分析（chat_with_tools，无工具）
├── memory_manager: MemoryManager     # 好感度落在 profile.json
├── analyze_and_update_affinity(npc_name, npc_reply, player_message)
├── get_affinity_level(affinity)      # 分数 -> 等级
├── get_affinity_modifier(affinity)   # 分数 -> 语气修饰文案
└── _create_analyzer_prompt(...)      # 分析提示词
```

> 注意: 好感度不是存在 `affinity_scores` 这种内存字典里，而是每个NPC自己的 `profile.json`，所以重启后仍然保留。

### 情感分析流程

```
1. 玩家发送消息
   ↓
2. NPC的ReActAgent生成回复（agents.chat 内 agent.run）
   ↓
3. 若NPC不是梓涵，调用 analyze_and_update_affinity
   ├── 组装"玩家说了什么 + NPC怎么回"
   ├── LLM返回JSON
   └── 解析 should_change / change_amount / reason / sentiment
   ↓
4. change_amount != 0 时更新档案
   ├── update_fact("affinity", str(变化量))  # 内部 += int(...)
   └── 重新读取得分、算新等级
   ↓
5. agents.py 打印变化日志
```

### 好感度变化规则

| 对话类型 | 变化量 | 示例 |
|---------|--------|------|
| 赞美、感谢、请教 | +3 到 +8 | "你真棒!" "谢谢你!" "能教教我吗?" |
| 友好问候、正常交流 | +1 到 +3 | "你好!" "最近怎么样?" |
| 普通闲聊、中性话题 | 0 | "今天天气不错" |
| 批评、质疑、不耐烦 | -3 到 -8 | "这个不太好" "真的吗?" |
| 侮辱、攻击、恶意 | -8 到 -15 | "你太烂了!" |

输出格式（提示词里约定的JSON）:
```json
{
    "should_change": true,
    "change_amount": 5,
    "reason": "友好问候",
    "sentiment": "positive"
}
```

## 🚀 API接口

### 1. 获取NPC好感度

```http
GET /npcs/子涵/affinity
```

**响应:**
```json
{
    "score": 41.0,
    "level": "友好",
    "modifier": "礼貌友善,正常交流,保持专业"
}
```

### 2. 获取所有NPC好感度

```http
GET /affinities
```

**响应**（只含四位专家，梓涵没有好感度）:
```json
{
    "子涵": {"score": 41.0, "level": "友好", "modifier": "礼貌友善,正常交流,保持专业"},
    "芷涵": {"score": 0.0, "level": "陌生", "modifier": "冷淡疏离,不太愿意多说"},
    "子晗": {"score": 62.0, "level": "亲密", "modifier": "友好热情,愿意多聊,会主动关心对方"},
    "子寒": {"score": 12.0, "level": "陌生", "modifier": "冷淡疏离,不太愿意多说"}
}
```

### 3. 设置NPC好感度 (测试用)

```http
PUT /npcs/子涵/affinity?affinity=80
```

**响应:**
```json
{
    "message": "已设置 子涵 好感度为 80"
}
```

**注意**: 代码里走的是 `update_fact`（累加），所以这个接口实际是"在当前分数上再加 int(affinity)"，不是覆盖。想清零请直接编辑 `profile.json` 或删除该目录。

## 🖥️ 前端展示（Godot）

好感度现在有两处可视化，数据都来自上面三个接口，后端不用改。

### 1. 对话面板顶部（每轮对话可见）
- 名字右侧一条 200×8 的细进度条，右边一行「41 · 友好」
- 打开对话时请求一次 `/npcs/{name}/affinity`；**每轮收到回复后再请求一次**——后端是"先更新档案再返回"，所以这一刻拿到的就是最新值
- 分数用 0.8 秒 Tween 滚动到新值，变化量以 `+5` / `-9` 浮字淡出
- 五档配色: 陌生 灰、熟悉 青、友好 绿、亲密 琥珀、挚友 粉紫
- 梓涵不画条，显示「导游 · 不记录好感度」（后端确实不打分）
- 接口 5 秒超时、失败静默，条上显示 `--`，不影响对话

### 2. TAB 关系档案面板（俯视全局）
- 左上角面板，列出子涵/芷涵/子晗/子寒的「名字 · 等级」「分值」「进度条」
- 按 TAB 开关；打开时请求 `/affinities`，打开期间每 10 秒刷新一次，对话收到回复时也会顺手刷
- 在输入框里打字时 TAB 不抢焦点，留给 LineEdit

## 📊 好感度系统配置

### 情感分析提示词

提示词在 `relationship_manager.py` 的 `_create_analyzer_prompt` 里，约定的分析维度:

```
【分析维度】
1. 玩家态度: 友好/中立/不友好
2. 对话内容: 积极/中立/消极
3. 互动质量: 深入/一般/敷衍
4. 情感倾向: 赞美/批评/中性
```

### 调整建议

- **更敏感**: 把变化量范围改成 -20 到 +15
- **更保守**: 改成 -5 到 +5
- **更细腻**: 增加"是否真诚"“是否重复提问"等维度
- **更省成本**: 只在对话轮次是3的倍数时才分析

### 等级阈值

```python
# relationship_manager.py
>= 80 → 挚友
>= 60 → 亲密
>= 40 → 友好
>= 20 → 熟悉
其他 → 陌生
```

## ❓ 常见问题

### Q1: 好感度为什么没有变化?

**可能原因:**
- 对话内容中性，模型判定 `should_change = false`
- 模型输出的JSON解析失败（被兜底成不变化）
- 聊的是梓涵（导游不打分）

**解决方法:**
- 用更明确的情感表达
- 加调试输出看模型原始返回
- 换一个NPC验证

### Q2: 好感度变化太快/太慢?

**解决方法:**
- 改 `_create_analyzer_prompt` 中的变化量区间
- 用 `PUT /npcs/{name}/affinity?affinity=...` 手动调整起点（记得是累加）

### Q3: 分数超过100或变成负数?

**原因:** `update_fact` 累加时不裁剪，只有 `analyze_and_update_affinity` 的返回值裁到 0-100。档案里可能存了 105 或 -3。

**解决:** 需要严格区间时，在 `main.py` 的 `set_npc_affinity` 或 `update_fact` 调用处补一次 `max(0, min(100, x))`。

### Q4: 为什么梓涵没有好感度?

**原因:** 梓涵是导游，多智能体的协调者，`agents.chat` 明确跳过对她的打分，`/affinities` 也排除她。
